### 🔴 HIGH

#### H1 ✔ 任意檔案寫入 → 儲存型 XSS／前端污染（`upload_map_image`）
- **證據**：`command-dashboard/src/routers/map.py:207-213`
  ```python
  filename = file.filename or "map.jpg"      # 攻擊者全控
  ext = filename.rsplit(".", 1)[-1].lower()  # 只看副檔名
  save_path = STATIC_DIR / filename          # 無 basename/../絕對路徑清洗
  save_path.write_bytes(content)
  ```
- 【事實】`file.filename` 來自 multipart，Starlette/python-multipart 不清洗。`STATIC_DIR / "../../x"` 或絕對路徑 `C:/...` 可逃出 static 目錄；允許 `svg` → 內含 `<script>` 寫進公開 `static/` 即儲存型 XSS。
- **角色閘**：`role_enum.py:103-104` → `COMMAND_ROLES`（commander/sysadmin），非 operator。故 HIGH 非 CRITICAL。
- **可利用**：持 commander session 者上傳 `filename=../../static/js/main.js` 覆寫前端 JS → 污染所有後續登入者（含 sysadmin）= 提權 / 全站接管；或寫任意路徑落檔。
- **修補**：`os.path.basename()` + `resolve()`+`is_relative_to(STATIC_DIR)` 二次守門 + uuid 重命名 + 移除/消毒 svg；依 User Data 紅線改落 `data/` 而非 `static/`。

#### H2 ✔ TTX router 整組無角色細分 + 無演習 scope（broken access control）
- **證據**：`auth/role_enum.py:82-147` 的 `allowed_roles_for` **完全沒有 `/api/ttx/` 分支** → 落預設 `:145-147`（GET→READ_ROLES、其餘→WRITE_ROLES）。`routers/ttx.py` 只 `validate_session`、`exercise_id` 直接吃 path/query，無 `resolve_scope`；`ttx_repo.get_ttx_injects` 純 `WHERE exercise_id=?`。
- **可利用**：observer → `GET /api/ttx/exercises/{任意id}/injects` 讀別場 inject 腳本（跨場洩漏）；operator → `POST .../injects/{id}/push` 把偽造 event/decision/snapshot 注入**任意演習場（含已歸檔）**污染 AAR。
- **修補**：`allowed_roles_for` 補 `/api/ttx/` case（push/load 應 COMMAND_ROLES）；ttx.py 讀寫一律走 `resolve_scope`。

#### H3 ✔ 事件寫入 IDOR + 跨演習越權
- **證據**：`routers/events.py` 讀取（`:58 get_ev`、`:73 get_chain`）有 `resolve_scope`，**寫入全無**：`:79 patch_ev`、`:92 patch_deadline`、`:105 patch_status`、`:114 add_note` 皆只認 `event_id`；repo `event_repo.patch_event/update_event_status/add_event_note` 全 `WHERE id=?`。中央 gate 對 `/api/events/` 非 GET → 預設 WRITE_ROLES（operator 可達）。
- **可利用**：operator 猜/列舉 event_id（`EV-MMDD-NNN` 易猜）→ 改別場（含歷史場）事件狀態為 resolved、竄改 assigned_unit/location、灌 note。讀嚴寫鬆的系統性不對稱。
- **修補**：寫入前 `resolve_scope`，repo 加 exercise_id 條件；不在 scope → 404。**同型還有 H3b**。

#### H3b ✔ 決策裁示 IDOR（同 H3 模式）
- **證據**：`routers/decisions.py:24-28 decide(decision_id)` 無 scope；`decision_repo.decide:57-69` `WHERE id=?`。`get_dec:18-21` 讀取有 scope，寫入無。operator 可達。
- **可利用**：operator 帶別場 decision_id 直接核准/否決他場待裁指令——作戰語意嚴重。

#### H4 ✔ 公網 Docker nginx 缺 security headers（HSTS/X-Frame-Options/X-Content-Type-Options/Referrer-Policy）
- **證據**：grep `deploy/ics-validation/`（含 prod 對外的 `mtls/nginx.mtls.conf` 與 `nginx.conf`）只有 `ssl_protocols`，**零 `add_header`、零 `include security-headers`、零 `ssl_ciphers`**。後端 `core/security_headers.py:4-7` 明文「HSTS/X-Frame-Options/X-Content-Type-Options/Referrer-Policy 由 nginx 注入」，後端只發 CSP。systemd 路徑（`deploy/nginx/conf.d/command.conf:52`）有 include，但 prod 走 Docker，不經此。
- **可利用**：對外 HTTPS 無 HSTS（SSL-strip 窗口）、無 X-Frame-Options（clickjacking，CSP frame-ancestors 僅對 enforce 頁+支援瀏覽器有效）、無 nosniff。指揮系統 clickjacking 價值高。另無 `ssl_ciphers` → 用 OpenSSL 預設 cipher（需 runtime 實測）。
- **修補**：在兩份 docker nginx server block include/補等價 `add_header ... always` + 明確 cipher suite。改一檔即補。

#### H5 Docker port-publish 抹除真實 client IP → 所有 per-IP 防護失效（專案已自認）
- **證據**：`deploy/perimeter/README.md:6-15` 自述 `ports:["443:443"]` 使 nginx/後端看到的 client IP 全為 bridge gateway `172.19.0.1`。連帶 `auth/rate_limit.py:24`（login 10/min/IP）、`mtls/nginx.mtls.conf` limit_req、fail2ban `jail.d/ics.local`、`_client_ip` 信任 X-Real-IP 全失效（全網一桶）。
- **可利用**：① 攻擊者打滿全域 login 配額 → 合法指揮官登不進（可用性攻擊）；② fail2ban ban gateway = ban 全部人。**mTLS 是目前唯一有效的網路層准入**。
- **修補**：README 已給正解——Tailscale/WireGuard 前置（埠不對公網 + 還原真 IP）或 Linux `network_mode: host`。**IP 還原前所有 per-IP 防護視為不存在**。

#### H6 mTLS 驗證棧 compose 寫死公開預設密碼（CA provisioner blast radius 最大）
- **證據**：`deploy/ics-validation/docker-compose.mtls.yml`：L22 `DOCKER_STEPCA_INIT_PASSWORD=icsprov`（硬寫、無 env 覆寫）、L70/L91 `ICS_PROXY_SHARED_SECRET:-ics-stack-proxy-secret-change-me`（後端+nginx 同預設）、L113 `ICS_CLIENT_P12_PASS:-icsclient`；`mtls/ca-bootstrap.sh:15`、`issue-client.sh:15` 同。
- **可利用**：此棧檔頭自述「用於公網 Windows/Docker 驗證」。若直接 `up` 未覆寫：CA provisioner 密碼 `icsprov` 公開 → 能連 step-ca:9000 者可請簽**任意 CN client 憑證**冒充任一裝置繞 mTLS；`...change-me` 公開 → #280「防內網偽造 cert header」失效。
- **緩解現況**：正式 systemd 路徑 `deploy/setup.sh:286-305` 用 `/dev/urandom` 產隨機 proxy secret（**那條路徑安全**）。風險限於「直接拿 compose.mtls.yml 上公網」。
- **修補**：compose 移除所有 `:-` 預設改 `${VAR:?must set}`（fail-closed）；`DOCKER_STEPCA_INIT_PASSWORD` 改 `${STEP_CA_PASSWORD:?}`。
